BIOS updates from **Fleet tasks → Firmware** now actually apply on Dell PCs that use BitLocker. Until now, none did. The update tool ran and said the image was staged, the PC restarted, and it came back on its old BIOS, with nothing anywhere saying why. When a flash still does not apply, the console now shows why.

This is a minor rather than a patch because it changes what a firmware update does to a PC (it suspends BitLocker), and it sends the hub new details with every firmware result.

**Deploy the hub first, as always.** This needs hub 1.139.0. On an older hub, this agent never suspends BitLocker, because the setting that switches it on comes from the hub.

## BitLocker is suspended for one restart

A BIOS update changes the measurements that BitLocker's key is sealed to. If BitLocker is still on, the update tool stages the image, but it is not applied on the next restart. Dell's own instructions are to suspend BitLocker before a BIOS update, and this release does that for you:

- **Just before the update tool runs**, the agent suspends BitLocker on the system drive, **for one restart only**. Windows turns it back on by itself after that restart, so it cannot stay off by accident, even if the agent crashes.
- **If the update fails, is cancelled or times out**, BitLocker is turned back on at once, because no restart is needed.
- It only happens during a firmware update you started. Nothing else in the agent touches BitLocker.

**What it costs:** between the update and the restart, the drive's key is stored on the disk unprotected. Anyone with the PC in hand during that window can read the drive without the PIN or the recovery key. Restart soon after a flash, which you need to do anyway for the update to apply.

**To turn it off**, switch off *Suspend BitLocker for one restart* under Settings → Firmware. That applies to the whole fleet. Firmware updates on PCs with BitLocker on are then likely to stage and never apply, as they did before this release.

## When a flash does not apply, the console says why

Each machine's row under **Recent updates** now shows:

- **The update tool's exit code.**
- **The BitLocker state**: off, suspended, left on because of the setting, or the error if suspending it failed.
- **The last part of the update tool's own log**, under *Update tool log*. Dell updaters now write that log automatically, unless the update's install switches already name a log file with `/l=`. **The BIOS setup password is blanked out of the log** before it leaves the PC, because Dell takes the password on its command line and the log can repeat it.

A full log is also kept on the PC for 30 days, in the agent's `firmware\logs` folder, named after the update.

The hub also no longer waits a day to give up. Once a PC has restarted after a flash and still reports its old BIOS version, the update is marked **Failed** within about ten minutes of the PC checking in, and the image can be edited or deleted again. That part is hub 1.139.0 and works with any agent.

## "Dell" now matches "Dell Inc."

An image whose manufacturer was typed as `Dell` used to be refused on every PC, because Windows reports `Dell Inc.`. Both the hub and the agent now treat those as the same manufacturer, and likewise `HP` and `Hewlett-Packard`. **Models still have to match exactly.** The model list is what stops an image being flashed onto the wrong hardware, and that check has not changed.

## The usual

**What you need to do:** nothing, beyond deploying hub 1.139.0 first. It arrives the way every agent update does, within about fifteen minutes.

**Installing an agent update restarts the service**, which drops any remote session or terminal open at that moment. Reconnect and it behaves normally.

**If it misbehaves.**

- **Check the agent version first.** The machine page should read 3.41.0. A firmware row with no exit code and no log came from an older agent.
- **The flash still did not apply.** Open the machine's row under *Recent updates* and read *Update tool log*. That log is the Dell tool's own account of what it did, and it is what to report, with the machine name and the exit code.
- **BitLocker shows an error.** The flash still ran, but probably will not apply. The error names what Windows refused. Suspend BitLocker by hand on that PC (`manage-bde -protectors -disable C: -rebootcount 1`) and flash it again.
- **A PC asks for its BitLocker recovery key after a flash.** That should not happen with this release. Report it with the machine name. The recovery key is under the machine's Security card, if escrow is on.

**Which hub you need.** Hub 1.139.0 or later. The ordinary rule applies: hub first, then let the agent arrive on its own.
