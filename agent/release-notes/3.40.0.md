Every PC now measures its own disks once a day, so the console can show what is filling a disk and roughly when it will be full. In the machine's **Files** tab, every folder shows its size. Right-click any folder or file for its **Size history**. **History** shows what changed between two days, down to single files, and can put the folder list beside how it looked on any past day.

This is a minor rather than a patch because it adds a command the hub gates on (*Scan now*) and a report the hub reads.

**Deploy the hub first, as always.** This needs hub 1.138.0. Some of it already works without this agent: hub 1.138.0 builds the *Full in about N days* estimate on the drive list from data every agent already sends. What needs 3.40.0 is everything below a drive: folder sizes, *Size history*, *What changed* and *Compare with*.

## Folder sizes, and what changed

Once a day each PC reads the file table of every local NTFS drive, the way WizTree does, rather than opening every folder. It reads a list Windows already keeps; it does not open your files, and it never reads their contents. On the first PC it ran on, a 100 GB system drive with about 400,000 files, that took 10 seconds.

What you will see once a PC has scanned:

- **Sizes in the Files tab.** Every folder shows its total, with a bar against the biggest on screen, and the Size heading sorts by it. A line under the toolbar says when the sizes were measured. They are from the last daily scan, not live.
- **Size history** on the right-click menu, for any folder or file, at any depth.
- **History → What changed.** For each scan:
  - the folders that grew or shrank by more than 64 MB, each named at the deepest folder that explains the change (the Outlook cache folder, not the five folders above it)
  - the individual files that grew, appeared or went away
  - new files over 100 MB
- **History → Compare with.** Pick a past day and the folder list gains a column with each entry's size on that day, and lists what has been deleted since.
- **Scan now** in the toolbar measures at the PC's next check-in instead of tomorrow.

**The first scan happens 5 to 60 minutes after the update arrives**, at a random point so that a whole office does not read its disks at the same moment. After that it is every 24 hours, and the time survives restarts and updates. *What changed* needs two scans, so it fills in on the second day.

## What it costs

- **On the PC**: once a day, about 10 seconds of reading at low disk priority, on a thread that gives way to whatever the person at the PC is doing, and about 200 MB of memory while it runs. Expect longer on a spinning disk and on drives with millions of files.
- **On the network**: the first day, one upload of the whole folder list per drive. That was 7 MB compressed for a 100 GB system drive with 400,000 files. After that, only what changed since the day before, usually well under a megabyte.
- **On the hub**: a few hundred MB per drive per year, kept under `logs/disk_history/`. The first day of the rollout, the hub works through one full list per PC, one after another, so History fills in over the first hour or so on a large fleet.

## What is now stored about people

**The hub now keeps the name and size of every file and folder on every scanned drive, including other people's profiles, for up to a year.** That is what makes *Size history* and *Compare with* possible.

- Only operators who can browse a machine's files (Issue commands, with the machine in their scope) can see it.
- Deleting a machine erases it. Retention is under Settings, as *Keep daily disk usage for* (90 days) and *Keep weekly disk usage for* (365 days).
- On the PC itself, the agent's copy is readable only by SYSTEM and Administrators.

If your organisation needs to tell staff what is recorded about their PCs, this belongs in that notice.

## What is not scanned

Only local NTFS drives. ReFS and FAT drives, USB sticks, network drives and BitLocker drives that are still locked are skipped. They keep the *Full in about N days* estimate, which does not need a scan. Their folders show a dash. The hub records why each one was skipped, but this release does not show that reason in the console yet.

## The usual

**What you need to do: nothing.** It arrives the way every agent update does, within about fifteen minutes.

**Installing an agent update restarts the service**, which drops any remote session or terminal open at that moment. Reconnect and it behaves normally.

**If it misbehaves.**

- **Check the agent version first.** The machine page should read 3.40.0.
- **Folders still show a dash.** The Files tab says "Folder sizes appear after the machine's first daily disk scan" until the first scan has run. *Scan now* starts it within a minute. If they are still missing an hour later, look in the agent's `companion.log` for a line starting `Disk usage:`. A successful scan logs the time it took, the number of folders and files, and the peak memory. A failed one names the drive and the Windows error, and that error is what to report, with the machine name.
- **History is empty but sizes show.** The upload has not reached the hub yet, or the hub is still working through the first day's queue.
- **This is the first release to read file tables on machines other than the one it was built on.** A drive that looks very wrong (sizes far from what Explorer's Properties dialog says, for example) is worth reporting with the drive's size and file system.

**Which hub you need.** Hub 1.138.0 or later. The ordinary rule applies: hub first, then let the agent arrive on its own.
