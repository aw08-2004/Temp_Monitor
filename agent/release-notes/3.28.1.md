A security update to the library behind remote view/control. Nothing changes on screen.

**Everything 3.28.0 added, plus a patched WebRTC library.** If you never saw 3.28.1's
predecessor arrive on your machines, that is why: 3.28.0 was built and published, then held
back rather than shipped, because the library it was built against had just been found
vulnerable. This release is that same work — the machine page updating every second while you
have it open — on a fixed library. The 3.28.0 notes describe the feature, and still apply
in full, including needing hub 1.77.0 or newer for the faster page.

**What was wrong.** Remote control runs over WebRTC, and the library that speaks it,
SIPSorcery, had two high-severity denial-of-service advisories against the version we were
on. One of them reaches this agent: a malformed SCTP acknowledgement chunk reads past the
end of a buffer, and that parsing happens before anything has decided whose packet it is.
The other concerns hosting a TURN relay server, which the agent never does — it only ever
connects to one — so it did not apply to us. Fixed by moving to SIPSorcery 10.0.15.

**What it could have done, honestly.** Crash a remote session. It is not remote code
execution, it does not expose the screen, the files, or anything else on the machine, and
nothing suggests it was used against anyone. The realistic case is a remote session that
dies and has to be reopened. It is being treated as worth its own release anyway, because
the damage is done by a packet, on software that sits on every machine in the fleet.

**What you need to do: nothing.** It arrives the way every agent update does, within about
fifteen minutes. Machines that never use remote view/control were never exposed and still
get the update, since it is the same agent.

**One thing to expect.** Installing an agent update restarts the service, which drops any
remote session that is open at that moment. A machine you are actively controlling as the
update lands will disconnect once; reconnect and it behaves normally. Telemetry, commands
and the machine page are unaffected — those reconnect on their own.

**If it misbehaves.** Check the version on the machine page: it should read 3.28.1. A remote
session that will not open after the update is worth a look at `remote-helper.log` on that
machine, but nothing in this release changed how sessions are set up — only the parsing of
packets inside one already running.
