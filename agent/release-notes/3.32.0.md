One change, and it only affects scripts a **rule** runs. Nothing changes for scripts you run
yourself from the Terminal tab.

**What was wrong.** The agent keeps one long-lived PowerShell (or cmd) per operator, on
purpose: when you type at the Terminal tab, your `cd` is still there on the next command, your
variables are still set, and that is what makes it feel like a real terminal on the box. The
shell is keyed on whoever issued the command.

A rule is issued as `rule:<id>`, so every rule got a shell too — and kept it. Every firing of
that rule on that machine landed in the **same** PowerShell process, reused for as long as the
session stayed warm, still carrying the previous firing's working directory, its variables and
any modules it had imported.

That makes a rule's script not reproducible from its own text. A script that changes directory
quietly changes what the *next* firing's relative paths mean. One that sets a variable leaves it
set. A script that works when you test it can behave differently at 3am on its fortieth run, and
nobody is watching to notice.

**What changed.** A script run by a rule now gets a **fresh shell every time** — the session is
discarded once the submission finishes. Every firing starts from the same state. Scripts you run
by hand are untouched and still persist between commands, because there the persistence is the
point.

**What you need to do: nothing.** It arrives the way every agent update does, within about
fifteen minutes. The one thing worth knowing: if you wrote a rule script that *relied* on state
left behind by its previous run, it will stop working — and it was already unreliable, because
the shell could be reaped at any time by the idle timer. Make such a script set up whatever it
needs at the top.

**Costs one process start per firing.** On a rule that fires every few minutes at worst, that is
not measurable.

**One thing to expect.** Installing an agent update restarts the service, which drops any remote
session open at that moment. Reconnect and it behaves normally. Telemetry, commands and the
machine page reconnect on their own.

**Pairs with hub 1.81.0**, which adds the Scripts library and gives every rule command a real
parameter editor. The agent change stands on its own, but the two shipped together.
