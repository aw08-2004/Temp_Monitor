One new thing, and it is small to describe and awkward to live without: the Files tool can now
**open** what you are looking at, instead of only moving it.

**This one needs the hub first.** The button is drawn by the hub and answered by the agent, so
a machine on 3.34.0 talking to a hub below 1.89.0 is simply never asked, and behaves exactly as
it did before. Update the hub, then let the agent arrive on its own.

## Open

Select one item in the **Files** tab and press **Open** — or double-click the row, which does
the same thing. You are then asked two questions, and both of them matter.

### Where should it open?

**On that PC.** The file opens over there, on the machine, the way it would if somebody
double-clicked it themselves. A document opens in whatever program that machine has registered
for it, a folder opens an Explorer window, a program starts.

**Here, in this browser.** The file comes to you instead, the same way a download does, and is
shown in the console: text and logs as text, images as images, PDFs in a viewer. Nothing runs.
Anything else — an .xlsx, a .zip — is not shown; you get the Save link and open it yourself.
This half is not offered for a folder, which has no contents to render.

### Open it as?

Only asked for a launch on the machine, and it is the half worth reading once.

**The signed-in user.** The program runs as the person sitting at that PC, on their desktop,
with their profile and their mapped drives — and they can see it. This is what "open their
invoice for them" means: their Word, their printer, their recent-files list. If nobody is
signed in, nothing is started and the tool says so, rather than opening a window onto an empty
desk.

**The system account.** The program runs as the agent does: full rights, session 0, **no
desktop**. Nothing it opens is visible to anybody, including the person at that machine. That
is the right answer for an installer or a script that has no window to begin with, and the
wrong one for a document — so a document opened this way is **refused** rather than started,
because the alternative is a WINWORD.EXE nobody can see, holding a file open, that only Task
Manager can end.

Neither answer is remembered between opens. "As the system account", chosen for an installer
twenty minutes ago and quietly reapplied to somebody's spreadsheet, is exactly the surprise
these two modes exist to prevent.

## What it will not do

**There is no Run box.** What gets opened is always the item selected in the list, which is
also what the audit log records. If you want to type a command, the Terminal tab is next door
and has not changed.

**It does not tell you what happened next.** The tool reports that the program started, as
which account and in which session, and then it is that machine's program — the console does
not follow it, and closing the panel does not close it.

**A folder can only be opened on the machine.** There is nothing to preview here.

## Who can use it

**Issue commands**, the same permission the rest of the Files tab and the terminal already
need. Nothing new is handed out: an operator who can open a program as the system account here
could already start one from the terminal, and the "signed-in user" half is *less* reach than
that shell, not more. Every open is recorded in the audit log against the operator who clicked
it, with the path and the account.

## The usual

**What you need to do: nothing**, beyond updating the hub first. It arrives the way every
agent update does, within about fifteen minutes.

**Installing an agent update restarts the service**, which drops any remote session or terminal
open at that moment. Reconnect and it behaves normally. Telemetry, commands and the machine
page reconnect on their own.

**If it misbehaves.** Check the version on the machine page: it should read 3.34.0. If Open
says the machine needs a newer agent, that machine has not updated yet — the rest of the Files
tab keeps working meanwhile, and only that one button waits. If a launch as the signed-in user
fails, `companion.log` on that machine names the Windows error; the commonest one by far is
that nobody was actually signed in.
