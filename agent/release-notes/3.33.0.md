One new feature, and it is the reason to take this update: the hub can now browse the files on
a managed machine, and move files on and off it, without anybody opening a terminal.

**This one needs the hub first.** Everything below is answered by the agent but asked by the
hub, so a machine on 3.33.0 talking to a hub below 1.88.0 simply never gets asked and behaves
exactly as it did before. Update the hub, then let the agent arrive on its own.

## The Files tool

The console's Tools page has a **Files** tab. Pick a machine and you get its drives, then its
folders, with **Download**, **Upload**, **Copy**, **Cut/Paste**, **Rename**, **New folder** and
**Delete**.

**What you will notice.** The two calls that used to mean opening a SYSTEM shell now do not.
"The report is on my desktop and I can't open it" is a download. "Put this driver in C:\Temp
for me" is an upload — which the terminal could not do at all, at any length, because a
terminal moves text and not bytes.

**Downloading a folder gives you a zip.** The machine builds it, so a 200 MB folder of source
is a 30 MB transfer over the link that is actually slow, and the console names the download
`<folder>.zip` so what you save matches what is inside it.

**A download is not instant, and the tool says which stage it is at.** The machine has to hear
about the request, read the file and upload it to the hub before your browser can collect it —
your browser and the machine are never on the same network at the same moment, which is the
whole reason this product works the way it does. So you get "fetching from the machine" and
then a Save link, rather than a click that appears to do nothing for half a minute. The link
keeps working for an hour if you get distracted.

**A file that something else has open still downloads.** The agent takes its own copy first
rather than holding the file open for the length of the upload, so an open Outlook data file
or a log something is writing to comes across without locking it or failing.

**Nothing is capped in a way you will hit by accident.** Two gigabytes per transfer either
direction, and a folder listing shows up to 2,000 items — past which the tool says how many it
is not showing rather than quietly presenting a short list as the whole folder.

## Deleting from here is permanent

**Read this once.** The agent runs as the system account and has no desktop of its own, so a
file deleted through the Files tool does not go to the Recycle Bin the person at the PC can
see. It would land in the system account's, where they cannot reach it. There is no undo.

The console confirms every deletion by name — it lists exactly what is about to go, rather
than counting it — and says the same thing there. This is the one action in the tool that
destroys something, and it is worth knowing before the first time you use it rather than
after.

## What it will not do

An operator asking for a folder they have no rights to gets **"Access is denied" as the
answer**, shown in the panel, rather than a spinner or an error that looks like a broken
console. The same is true of a file that has been deleted since the list was drawn, a drive
that is not ready, and a machine that is asleep.

**Copying or moving a folder into itself is refused** at three separate points, because that
is the one mistake here that destroys data instead of failing — the copy walks into the copy
it is making until the disk is full. **Whole drives cannot be deleted, copied or moved.** A
file already at the destination is **not replaced** unless you tick the box that says so.

**A move across drives is a copy and then a delete, in that order.** The delete only runs if
the copy finished, so an interrupted move leaves the file where it started rather than
nowhere.

## Who can use it

The Files tab needs **Issue commands**, the same permission that already covers the terminal,
restarts and shutdowns — including for *browsing*, not just for changing things. That is
deliberate. A folder listing is not the same kind of thing as a temperature reading: those are
the names of somebody's documents, and the same door reads what is in them. Anyone who has
this permission could already read any file on the machine by typing at the terminal, so
nothing new is being handed out; what it prevents is everyone who can see a machine's graphs
also being able to read every user's files.

Every folder somebody opens is recorded in the hub's audit log, against the operator who
opened it. That is a change from the Processes card, which is not audited per refresh — the
difference is that browsing happens a click at a time, and "who opened that folder, and when"
is a question worth being able to answer.

## The usual

**What you need to do: nothing**, beyond updating the hub first. It arrives the way every
agent update does, within about fifteen minutes.

**Installing an agent update restarts the service**, which drops any remote session or
terminal open at that moment. Reconnect and it behaves normally. Telemetry, commands and the
machine page reconnect on their own.

**If it misbehaves.** Check the version on the machine page: it should read 3.33.0. If the
Files tab says the machine needs a newer agent, that machine has not updated yet — the tab
names the version it is waiting for rather than failing every click. A transfer that will not
finish is worth a look at `companion.log` on that machine; the agent logs what it could not
read or write, and the reason it gives is the one the console shows you.
