Every PC now tells the hub what is installed on it. That fills the Software section of the new device report and the software catalog on the Reports page, both of which shipped in hub 1.133.0 and have been reading "waiting for a newer agent" until this release.

This is a minor rather than a patch because it adds something the hub reads. Nothing on the console changes on its own the moment this arrives; a PC's Software section fills in within about an hour of it updating.

**Deploy the hub first, as always.** This needs hub 1.133.0. An agent on 3.38.0 talking to an older hub sends its software list and the hub ignores it -- harmless, and it is sent again once the hub understands it.

## Installed software

The question this answers is the one a helpdesk gets from a licence audit or a vulnerability notice: which PCs still have the old VPN client, who is on Acrobat 2017, what did that user install. Until now the fleet could only name software that had an update waiting; a fully patched program was invisible.

**Where to look.** The machine page has a new **Report** tab, with an **Open printable sheet** link for the page you print. **Reports** in the sidebar lists a whole device group -- or the rows you ticked on Devices, via **Report selected** -- and exports it as JSON or CSV. The **software catalog** at the bottom of Reports lists every program and version across the machines you can see, with how many have each; click a count to see which PCs.

**What it reads.** The same list Programs and Features shows: the registry's Uninstall entries for 64-bit and 32-bit programs, plus the per-user installs of everybody signed in to the PC at the time. Windows updates, hidden system components and sub-entries of other programs are left out, as they are in Control Panel. It deliberately does not use `Win32_Product`, which makes Windows Installer check -- and sometimes repair -- every MSI on the machine just by being asked.

**A program installed by somebody who is signed out does not appear until they sign in again.** Per-user installs (Zoom, Teams classic, some VS Code installs) live in that person's own registry hive, which Windows only loads while they are signed in. Loading every profile's hive on a schedule was the alternative, and it means touching the profile of somebody who might sign in halfway through; this release chose not to.

**When it updates.** Once an hour, and straight after a package deployment finishes -- successful or not, since a failed install can still leave something behind. It is only sent when the list has changed, so a settled PC sends it once.

**The Generative AI apps card uses this too.** Hub 1.133.0 added a watch list (Settings -> Endpoint Security) that flags ChatGPT, Claude, Copilot, Ollama and similar tools on the Reports page. It could only see Android phones until now. It flags; it blocks nothing.

## A bash script sent to a Windows PC is refused

Since hub 1.123.0 a rule can say its script is `bash` or `sh`, so it can target Linux machines. On Windows the agent treated any shell it did not recognise as PowerShell, which meant a bash script aimed at a PC by mistake ran anyway -- and `echo`, `cd` and `rm` all mean something in PowerShell, so it often half-worked and came back as succeeded.

It now fails straight away with `shell 'bash' is a Linux shell and cannot run on this Windows machine`. Scripts marked `powershell`, `cmd`, `batch` or `bat` are unchanged. **If a rule starts failing after this update, look at its shell setting**: it was not doing what it said before either.

## The usual

**What you need to do: nothing.** It arrives the way every agent update does, within about fifteen minutes.

**Installing an agent update restarts the service**, which drops any remote session or terminal open at that moment. Reconnect and it behaves normally.

**If it misbehaves.** Check the version on the machine page: it should read 3.38.0. A PC whose Software section still says "waiting for a newer agent" an hour after updating has not been able to read its registry. This release does not log why (the read is retried every hour, silently), so report the machine name. A list that looks short compared with Control Panel is worth reporting with the program names that are missing -- this is the first release to run against real registries rather than test data. If the section shows "truncated", that PC reported more than 2,000 entries and the rest were left out; per-user entries are the ones dropped first.

**Which hub you need.** Hub 1.133.0 or later. The ordinary rule applies: hub first, then let the agent arrive on its own.
